Two edges of one system

MCP standardizes the model to capability edge. A2A standardizes the agent to agent edge. They are not rivals.

A2A agent to agent
Your triage agent
codebase A

codebase B

Far side: a system that plans, loops, and decides. You need what a tool call throws away.

Ask what sits on the far side of the boundary. That decides the protocol.

A tool wrapper loses the durable task id, the cancellable unit of work, partial artifacts, and the peer's ability to ask for more input.

Migration note: IBM's Agent Communication Protocol, ACP, was a competing REST-based design. It is now folded into A2A under the Linux Foundation, so a vendor page advertising ACP support needs the question asked: retired standalone protocol, or the A2A successor?
