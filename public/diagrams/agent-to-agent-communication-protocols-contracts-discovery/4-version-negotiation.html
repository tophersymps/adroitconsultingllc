One data model, and a header you cannot forget

A2A separates the data model from the wire. Version negotiation is where a small omission causes a large outage.

Core bindings
JSONRPC GRPC HTTP+JSON
supportedInterfaces is ordered: the first entry is the preferred one
Explicit Client sends the A2A-Version header with every request
Request carries
A2A-Version: 1.0 as Major.Minor only
→
Server must
process the request under the semantics of the requested version
→
Or refuse loudly
VersionNotSupportedError at JSON-RPC -32009
Result: behavior matches the contract, or the client gets an error it can act on.
Silent Client forgets the header, or sends it empty
An empty version
is interpreted as 0.3
→
Server has 0.3 wired up
so the request is accepted under old semantics
→
Client sees
old behavior that looks like a new bug
Result: no error. This is the outage that takes a day to find.
Compatibility rule
Patch versions are ignored for compatibility. The header carries Major.Minor only.
Client rule
Send A2A-Version explicitly, and fail loudly rather than falling back to an older version.
Long-running work
Streaming for a connected client, push notifications where the server POSTs updates to a client webhook, polling as the third option.
