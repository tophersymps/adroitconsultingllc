Which lever moves the needle?

Plot the failure mode on two axes to pick where the change happens

Knowledge changes often

RAG (the default)

Docs, tickets, prices and products update constantly. Retrieve the current source instead of baking it in. The right call for roughly 80% of enterprise workloads.

Stable, narrow behavior

Fine-tune

A fixed schema, persona, tone or output format that prompting cannot hold. Bake the behavior into a thin adapter. Facts still come from retrieval.

Behavior keeps changing

Prompt first, not weights

Frequent target changes mean you have not settled the goal. Locking the current preference into weights pays to redo it next quarter.

Rare, distant vocabulary

Continued pre-training

Base model has never seen the domain language. Almost never the answer for product teams; only for genuinely distant, stable corpora.

Read as: knowledge that changes, the lever changes the facts you give it. Behavior that holds still, the lever changes the weights. They compose, they are not rivals.
