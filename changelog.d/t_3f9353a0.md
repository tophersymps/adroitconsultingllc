### Narrow the src/proxy.ts matcher to session-reading routes only (t_3f9353a0)

**What** - `src/proxy.ts` no longer matches every non-asset page. `config.matcher` is now an
explicit allow-list of the routes whose RENDER path reads auth/access state:

```ts
matcher: ["/admin/:path*", "/atlas/:path*", "/preview/:path*", "/profile", "/settings"]
```

The proxy body, the cookie handling and `src/lib/auth/transport.ts` are unchanged. Public
pages, `src/app/api/**`, static assets and `_next/*` stop invoking Proxy. New
`src/proxy.matcher.test.ts` pins the contract in both directions and also scans `src/app` so a
gated page added without a matcher clause fails the suite.

**Why** - adroit.io is on Vercel Hobby with a 10 GB/month Fast Origin Transfer cap and no
overage, so crossing 100 percent hard-pauses the project until the period resets. Fast Origin
Transfer is CDN-to-compute traffic in both directions, and a Middleware request can accrue it
twice. A production `vercel logs` sample on 2026-11-19 was 64 percent `serverless-middleware`,
and 28 of those 32 middleware records were `cache: PRERENDER`: the page HTML came from Vercel's
edge cache and Middleware still ran. The old catch-all matcher ran Proxy on every non-asset
page, so a guest reading a marketing page or a field note paid a compute round trip for a page
that is otherwise free CDN serving. Proxy only ever refreshed a session cookie and never
redirected, so the gated routes are the only ones that need it.

**Verified** - `npx tsc --noEmit` exit 0. `npm run lint` exit 0. `npm test` 198 files / 1939
tests passed. `npm run build` succeeded, and `.next/server/functions-config-manifest.json` now
lists exactly the five matchers above for `/_middleware`, with no catch-all. Dev-server request
logs on localhost:3000 show the proxy running only on gated paths: `GET /atlas 200 (...
proxy.ts: 1.7ms ...)`, `GET /profile 200 (... proxy.ts: ...)`, `GET /settings 307 (...
proxy.ts: ...)` versus `GET /field-notes 200 (next.js: 0.9ms, application-code: 29ms)`,
`GET /field-notes/categories 200` and `GET /api/auth/session 200` with no `proxy.ts` entry. A
request carrying a `neon-auth.session_token` cookie to `/atlas` and to `/profile` returned 200
with no redirect (the refresh leg still runs and still never blocks navigation when the upstream
fails). Guest spot checks: `/` 200 "Adroit Consulting"; `/field-notes` 200 "Field Notes | Adroit
Consulting"; `/field-notes/a2a-agent-coordination-2026` 200 with its real article title; `/tags`
200 "Tags - Field Notes - Adroit Consulting"; gated lesson `/atlas/agentic-ai/agent-loop-by-hand-
no-framework` 200 "Lesson 22: Building Without a Framework: the Agent Loop by Hand in 100 Lines |
Agentic AI Implementation Path | Adroit". The matcher test was proved to bite: dropping the
`/atlas/:path*` clause failed 8 assertions (7 explicit gated paths plus the filesystem scan), and
re-adding the old catch-all failed 17 (every public path plus the catch-all guard).
