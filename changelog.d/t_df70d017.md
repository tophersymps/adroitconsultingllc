### /atlas assessment heads gate `noindex` on the DB disclosure seam (t_df70d017)

**What** - `generateMetadata` on `/atlas/[series]/exam`, `/atlas/[series]/certificate` and
`/atlas/[series]/check/[n]` now answers its `robots` question with `mayDiscloseSeriesLive(series)`
(the DB disclosure seam) instead of `isPubliclyLaunchedSeries(series)` (the hand-maintained
`PUBLICLY_LAUNCHED_SERIES` mirror). That matches `/atlas/[series]` and `/atlas/[series]/[slug]`.
Each route keeps its `isPubliclyLaunchedSeries` import and its `degraded &&
!isPubliclyLaunchedSeries(series) -> notFound()` existence gate, byte for byte. `/atlas/[series]/preview`
is untouched (its metadata is `noindex, nofollow` on both branches, so the DB verdict buys nothing
there and its mirror check is the t_91a3e30b CWE-200 guard). The `PUBLICLY_LAUNCHED_SERIES` contract
comment in `src/lib/atlas-launch.ts` is corrected: it claimed the mirror is consumed on "exactly TWO
paths" while these three heads were an undocumented consumer; it now lists the three remaining paths
and states that the assessment heads reach the mirror only indirectly through the `null`
credential-outage branch of `mayDiscloseSeries`.

**Why** - a course launched from the admin backend (no migration, no mirror PR) was `live`,
non-stealth, in the hub and in the sitemap, yet its exam / certificate / knowledge-check heads stayed
`noindex` until a human added the slug to `PUBLICLY_LAUNCHED_SERIES`. `sf-agentforce-specialist` hit
exactly this on 2026-11-25. The sitemap already listed `/atlas/<series>/exam` and `/check/n` URLs
built from the DB seam, so the sitemap and the head disagreed about the same URL. No new cache layer
was added: the verdict relies on the existing per-request React `cache()` inside
`getCourseRowBySlug`, so a delist still takes effect on the next request (preserves t_b4c0da5f) and a
credential outage still fails closed to the mirror. Disclosure never grants access: `src/lib/access.ts`
is not touched, so the paywall and existence decisions in the page bodies are unchanged.

**Verified** - `npx vitest run`: 207 files, 2034 tests, all passing, including `atlas-launch.test.ts`
(mirror pinned both directions), `atlas-access-invariant.test.ts` (DISCLOSURE_NEVER_GRANTS_ACCESS) and
the new per-head disclosure suites. `npx tsc -p tsconfig.json --noEmit` exits 0, `npm run lint` exits
0, `npm run build` exits 0. The regression tests bite: reverting the predicate to the mirror turns the
three "DB-live series ABSENT from the static mirror" cases red with `expected { index: false, follow:
false } to deeply equal { index: true, follow: true }`, and restoring it turns them green. Against a
local `next dev` on the dev Neon branch, `/atlas/sf-agentforce-specialist/{exam,certificate,check/1}`
each return HTTP 200 with `<meta name="robots" content="index, follow">` and the real course title.
The DB-live set and the mirror are currently identical (12 slugs each, from `/sitemap.xml` vs the
mirror), so the synthetic-slug test is the discriminating before/after witness for this defect.

**Known Issues** - Under a credential outage a series absent from the mirror still renders the
generic `noindex` head and 404s; that is the fail-closed direction atlas-launch.ts documents and is
out of scope here. `[slug]/page.tsx`'s comment still describes the pre-t_47183b5b "mirror AND ..."
intersection; it is stale but not part of this change.
