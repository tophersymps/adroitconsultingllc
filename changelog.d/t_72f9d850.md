### Fix the build-time token mint that emptied /atlas (t_72f9d850)

**What** - Three changes in `src/lib/db/`, plus one new test suite.

1. New `src/lib/db/mint-transport.ts` (`server-only`): `mintFetch` issues the auth handshake through
   Next's own internal-fetch opt-out (`next: { internal: true }`), so it never enters Next's
   static-render fetch tracking, and `isNextDynamicUsageError` identifies Next's static-render
   bail-out signal (`digest === "DYNAMIC_SERVER_USAGE"`). `no-store` semantics, the shared 800 ms
   mint budget's `AbortSignal` and the existing cooldown are unchanged.
2. `src/lib/db/server.ts` sends the `/token` mint, the `/token/anonymous` mint and the `/get-session`
   lookup through `mintFetch`, and each of the three catches now RETHROWS that signal instead of
   classifying it as a network failure, so it never arms the mint cooldown. A genuine mint failure
   still degrades to the static launch mirror exactly as before.
3. `src/lib/db/anonymous-token.ts` and `src/lib/db/server-only-guard.test.ts` document and register
   the one deliberate rejection the mint may now produce.

**Why** - Every production build on adroit.io logged

    [learn-visibility] courses read failed, degrading learn visibility to the static launched-series mirror
    Error [DbTokenUnavailableError]: Neon Data API token is unavailable

and `/atlas` shipped 0 courses. Root cause: `next build` replaces `globalThis.fetch` with Next's
instrumented fetch, and a `cache: "no-store"` fetch issued while a route is being prerendered makes
the legacy prerender store bail out by THROWING `DynamicServerError` ("Route /field-notes/<slug>
couldn't be rendered statically because it used revalidate: 0 fetch"). The mint's generic `catch {}`
read that as a network failure, armed the process-wide mint cooldown (10-60 s plus jitter) and
circuit breaker, and every later DB read in that build process degraded. `/atlas` is
`force-static` + `revalidate = 3600`, so that degraded render was baked into the CDN-cached hub.
The Neon endpoint was never unhealthy.

**Verified** - Reproduced and fixed against a real `next build` on this worktree, with the data layer
pointed at a throwaway local stand-in for the Neon Auth mint and Data API (no live Neon credentials
were reachable from this workspace, so this is not a live-DB build).

Before the change, same tree, same stub: `npm run build` printed the two
`[learn-visibility] ... degrading` lines above with `db token unavailable { errorClass: 'network',
status: null }`. After the change: `npm run build` generated 1326/1326 static pages with ZERO
`[learn-visibility] ... degrading` lines, ZERO `DbTokenUnavailableError` lines and no
`/atlas build warning`, and the route table still shows `○ /atlas 1h 1y`. The prerendered
`.next/server/app/atlas.html` carries all four launched series as cards (the LearnHub props in
`atlas.rsc` hold the `agentic-ai`, `ai-at-work`, `omni-studio-cert` and `salesforce-architect`
series, and the page emits its `ItemList` JSON-LD). `npx vitest run` is green (197 files, 1903
tests), including the new `src/lib/db/mint-transport.test.ts` (10 tests) and the untouched
fail-closed/degraded suites; `npx tsc --noEmit` and `npx eslint` are clean on every touched file.

**Known Issues** - The last acceptance check, "a production deploy's `/atlas` HTML contains real
series cards", needs the merge and the Vercel deploy, so it is still open here. A build against the
live `dev-admin-ux` Neon branch was not run from this workspace: its `.env.local` was a symlink to a
removed directory, and pointing a local build at `production` is out of bounds. The local stand-in
exercises the code path that was broken (Next's patched fetch plus the real mint, seam and page
code); it cannot prove the live Data API answers, which the same page already did successfully
before this regression. The `next build` on this machine also exits 1 at the very END, after static
generation and the route table, on an injected Next.js security advisory gate that recommends
`next upgrade --agent=security`; it is unrelated to this change and present before it as well.
