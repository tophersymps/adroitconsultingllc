## Architecture

### Data Model

Supabase will host 3 tables:

```
table: read_progress
  id: uuid (PK, defaults: gen_random_uuid())
  user_id: uuid (NOT NULL, indexed)
  content_type: text CHECK (content_type IN ('blog', 'lesson'))
  content_slug: text (NOT NULL) — blog slug or lesson slug
  read_at: timestamptz (defaults: now())
  UNIQUE (user_id, content_slug)

table: lesson_completion
  id: uuid (PK, defaults: gen_random_uuid())
  user_id: uuid (NOT NULL, indexed)
  lesson_slug: text (NOT NULL)
  completed_at: timestamptz (defaults: now())
  UNIQUE (user_id, lesson_slug)

table: quiz_attempt
  id: uuid (PK, defaults: gen_random_uuid())
  user_id: uuid (NOT NULL, indexed)
  quiz_name: text (NOT NULL) — e.g. "day-01-f1"
  question_index: int (NOT NULL)
  correct_answer_index: int (NOT NULL)
  user_answer_index: int (NOT NULL)
  is_correct: boolean (NOT NULL)
  attempted_at: timestamptz (defaults: now())
```

### Client Architecture

```
┌─────────────────────────────────────────────────────┐
│                     Pages (Server)                    │
│  /blog/[slug], /learn/[series]/[slug]                │
│  ┌─────────────────────────────────────────────────┐ │
│  │  useReadProgress (client hook)                   │ │
│  │  ├── Supabase (authenticated user)               │ │
│  │  └── localStorage (guest / offline fallback)     │ │
│  └─────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────┐ │
│  │  useLessonProgress (client hook)                 │ │
│  │  ├── Supabase                                    │ │
│  │  └── localStorage                                │ │
│  └─────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────┐ │
│  │  useQuizProgress (client hook)                   │ │
│  │  └── localStorage only (ephemeral per session)   │ │
│  └─────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────┤
│                API Routes (Server)                    │
│  POST /api/progress/read — mark blog/lesson read     │
│  POST /api/progress/lesson — mark lesson complete     │
│  POST /api/progress/quiz — submit quiz attempt        │
│  GET  /api/progress/summary — get all progress data   │
├─────────────────────────────────────────────────────┤
│              Supabase Client Layer                    │
│  src/lib/supabase/client.ts — singleton client        │
│  src/lib/supabase/server.ts — server client helper    │
└─────────────────────────────────────────────────────┘
```

### Design Decisions

1. **localStorage fallback for guests:** Per mockup spec (§5.3), guests get localStorage-only tracking. Authenticated users sync to Supabase with localStorage as fallback.
2. **Quiz data stays client-side:** Per mockup spec (§5.4), quiz attempts are localStorage-only (ephemeral). The questions.json is the source of truth; no Supabase table for quiz answers is needed.
3. **Read tracking is optimistic:** POST to `/api/progress/read` is fire-and-forget with error handling. If it fails, localStorage stores the pending write.
4. **Lesson completion mirrors read tracking:** Same pattern — optimistic POST with localStorage fallback.
5. **Progress summary endpoint:** A single GET `/api/progress/summary` endpoint returns all progress data for a user, avoiding multiple round-trips on page load.

## Risks & Considerations

1. **Supabase auth setup:** The site currently has no auth. Task 1 should include a note about creating the Supabase project auth (email/password or magic link) — or the implementation should work with anonymous sessions initially.
2. **localStorage key collision:** Use namespaced keys: `adroit-blog:read:slug`, `adroit-blog:lesson:slug`, `adroit-blog:quiz:name`
3. **Server component constraints:** Progress hooks are client-side (`"use client"`). Server components must use the API route or pass progress data as props.
4. **Guest vs authenticated sync:** When a guest signs up, localStorage data should be synced to Supabase. This can be a deferred enhancement — initial implementation tracks guest and auth separately.
5. **Quiz questions.json format:** The questions.json files in `content/omni-studio-cert/` need a defined schema. The mockup shows 4-option MCQ with correct_answer_index and options.

## Acceptance Criteria

1. Guest user can mark blog posts as read — persists to localStorage
2. Guest user can mark lessons as complete — persists to localStorage
3. Guest user can take quizzes — results persist to localStorage
4. Authenticated user's progress syncs to Supabase
5. Progress bar appears on blog listing and post detail pages

7. Quiz page loads questions from questions.json files
8. `npm run build` passes with no errors
