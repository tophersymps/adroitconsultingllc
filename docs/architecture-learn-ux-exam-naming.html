Learn UX + Exam Naming — System Architecture

📅 October 25, 2026 📋 Adroit Learn (adroit-code) 👤 Brainiac · Web Solution Architect 📄 v1.0 (t_47db5c5e)

What this report covers

Two workstreams in one release for the Adroit Learn catalogue: A — lesson page information architecture (citations last, milestone checks as timeline nodes with routing into and out of the check, completion control in the sticky audio bar); B — kind-aware exam naming (explicit examKind, one label source, copy sweep across every exam surface including exam.json titles and the SEO head).

All four items must work on desktop and mobile (Amendment 1). Every card in this plan carries a viewport evidence requirement: 390×844, 360×800, 768×1024, 1280×800, 1440×900, plus 844×390 for the sticky bar.

Stack unchanged: Next.js App Router, TypeScript, server components, Tailwind tokens, vitest. No new runtime, service, data store, or write path. Two new libraries, one new hook, four new components, one retirement.

The four verified facts that shaped the design

FactEvidenceDesign consequence
Citations are auto-generated MDX footnotes, not a component remark-gfm emits one <section data-footnotes> at the end of the rendered tree; MDXArticle only renames its heading The split must happen inside the render pipeline, not in the page layout
A definitions-only MDX document renders nothing Probe: references need their definitions in the same document, and the footer is emitted only when references exist Both passes render the whole document with a rehype filter (drop / keep-only). No source-level split is possible
Two filtered renders are affordable Measured on a real 16 KB lesson: one compile 5.1 ms, two 7.9 ms +3–5 ms per lesson page; accepted against a force-dynamic page already making DB round trips
group is not a runtime value and is already wrong for agentic-ai build-learn.js:236, no group in the generated module, dropped in the degraded path Explicit required examKind in content, validated at build, surfaced through the generated module

Where things live (the three decisions the BA left open)

QuestionAnswerWhy there
How does the MDX renderer return body and sources as siblings without changing blog output? MDXArticle gains sources: "inline" | "split" (default inline) plus a shared rehype plugin module; a new MDXSources renders only the section Default-off means the four other callers (blog, two previews, paywall peek) cannot regress; the plugins are pure tree filters and unit-testable without React
Where does the lesson→check mapping helper live? src/lib/lesson-checks.ts Needed by a server page (routing, panel) and a client component (timeline), so it must be pure: no fs, no React. lib/quiz.ts is server-only (fs) and must not be imported by the syllabus
Where does the single exam label source live, and how does generated data carry examKind? src/lib/exam-labels.ts (copy only) + examKind emitted by build-learn.js into src/data/learn.ts A client-safe module cannot import the generated series module's neighbour lib/learn.ts (fs). So: copy in one place, kind resolved on the server and passed as a prop

Single-syllabus presentation with real nodesThe syllabus is already one column at every width, so a node is mobile-first by constructionA separate mobile component (double maintenance); a shrunk desktop table (explicitly rejected by Amendment 1)

Handoff guide for Kara (design)

  1. K1 — the milestone node. This is the highest-leverage surface: it must read as a milestone while sitting inside a list of lessons. Constraints are fixed (44 px target, no fixed width, not colour-only, mobile-first at 360 px); hierarchy, marker treatment and badge styling are yours.
  2. K2 — the sticky bar control. The hard problem is 360 px and landscape 844×390: the header row must not crowd the player or shrink the audio element. Decide whether "Follow along" collapses to an icon. Incomplete = button; complete = static chip (no toggle — un-marking stays in the hero control).
  3. K3 — sources at the bottom. Specify the separation from the check panel, URL wrapping at 320–360 px, tappable back-reference arrows, and the scroll-margin-top value as one CSS custom property.
  4. Copy is not yours to change in code. Exam labels come from examLabels(kind) and lesson body copy is authored. Propose wording to Lois; do not edit strings inline.
  5. C1 — annotate the old design files (design/copy-deck-quiz-tiers.md, the two exam mockups) so future design work does not copy the cert-prep label onto a course-completion exam.

Handoff guide for Steel (implementation)

  1. Treat deliverables/learn-ux-exam-naming/api-contracts.md as the seam. Changing a signature means updating that file in the same PR.
  2. Do not decide D-1, D-2 or D-3. Ship LESSON_GATE_MODE = "advisory" and agentic-ai = course-completion as seeded, and say so in the PR body.
  3. No new write path: completion goes through /api/progress/lesson via useLessonProgress, only.
  4. Every card's handoff carries the viewport table from Amendment 1. One viewport class is an unfinished item.
