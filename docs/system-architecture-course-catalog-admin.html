1. Architecture Summary

Adroit Learn becomes a course catalog with database-backed status + entitlements and an admin backend. Course lifecycle (status) and access model live in courses; who has access lives in user_roles + user_entitlements + subscriptions. A single server-side access seam (src/lib/access.ts) is the only place that turns those rows into visibility + access decisions. Every surface — catalog pages, content pages, sitemap, static params, APIs, admin — calls the seam. The seam and RLS agree; the server seam is the enforcement point, RLS is defense-in-depth.

Payment (Stripe) is explicitly out of scope but the model slots it in with zero access-logic changes. Blog stays public. Content stays in content/learn/; the DB never stores lesson bodies.

Non-negotiable (Plan v3): status + entitlements in the DB, never in content files. Content and platform touch disjoint repo areas (content/learn/ vs src/ + supabase/).

Seeding: migration inserts Chris as admin via a WHERE email = match against auth.users (idempotent, ON CONFLICT DO NOTHING). Users without a row default to member at read time.

Revoke = soft delete (revoked_at set, row kept for audit/matrix history). Access checks filter revoked_at IS NULL. Re-grant after revoke inserts a new active row.

is_admin() helper: a SECURITY DEFINER SQL function backing every policy so a raw client (anon key + JWT) can never read pending/archived courses, others’ entitlements, or the audit log.

3. Access Seam — src/lib/access.ts

The single decision function every surface calls. Server-only (never imported into client components). Three exports per the AccessSeam contract:

  • getCatalogForUser(userId) → CatalogForUserResult — visible courses + per-course access for a surface
  • decideCourseAccess(userId, seriesSlug) → CourseAccessDecision — granted | paywall | admin-preview | not-launched
  • isAdmin(userId) → boolean — role gate for /admin

Decision rules (mirror US-002 exactly):

  • No courses row for the series → not-launched (404 on content routes, admin-only in catalog).
  • Admin → admin-preview (pending/archived renders via dynamic MDX; no sitemap/JSON-LD).
  • Status not live and not admin → not-launched.
  • Live: free → granted (signed-in); granted → active user_entitlements row source granted; one-time → active row source one-time; subscription → active sub; sub-or-one-time → either.
  • Live + not entitled → paywall.

Implementation notes for steel: use getSupabaseServerClient() (cookie-bound, RLS) for per-user reads; getSupabaseServiceClient() only inside the admin API for validated writes. Cache the courses read per-request via React cache() to avoid N+1.

6. Data Flow

Member hits /learn/[series]/[slug]
  → server component
  → getSupabaseServerClient() (cookie → auth user)
  → src/lib/access.ts decideCourseAccess(userId, seriesSlug)
       ├─ load courses row (RLS: live visible)
       ├─ isAdmin? → admin-preview
       ├─ no row / not live → not-launched → notFound()
       ├─ live + entitled (model eval) → granted
       └─ live + not entitled → paywall
  → granted: render MDX content (content/learn//.mdx)
  → paywall: render <Paywall options={modelOptions} peek={firstLesson} />

Admin launches course
  → /admin → PATCH /api/admin/courses/[slug] {status:'live'}
  → isAdmin check (403 if not)
  → update courses row (service client) + set launched_at
  → insert admin_audit_log (course.launch)
  → next /learn request: getCatalogForUser returns course visible → public

12. Acceptance Criteria (for zod / QA)

  1. getCatalogForUser: live visible to all; pending/archived to admins only.
  2. decideCourseAccess: free→granted (signed-in); subscription/one-time/sub-or-one-time→entitled only; granted→entitlement row; no row/not live→not-launched.
  3. Non-entitled member on a live lesson sees the paywall (never content, never 404).
  4. Non-admin on /admin or /api/admin/* → 404/403 server-side.
  5. Sitemap + generateStaticParams exclude pending/archived.
  6. Grant/revoke/launch/role-change write + visibly confirm an audit-log row.
  7. Bulk grant writes one row per selected user.
  8. Blog routes unchanged and fully public.
  9. npm run build passes; access seam + gate tests green.

13. Risks

  • DB not pushed / RLS misconfigured → surfaces 500 or leak. Apply migration 008 in task A, verify policies, keep server seam authoritative.
  • courses row missing for an existing series → whole series 404s for members. Seed live rows for current published series in migration 008.
  • Force-dynamic cost — lesson/series pages already force-dynamic; seam adds a DB read per request. Cache courses per-request.
  • admin API origin/CSRF — apply existing checkOrigin + rate-limit to all admin POST/PATCH/DELETE.
  • Service client misuse — keep getSupabaseServiceClient() confined to admin API writes; never for resolving the current user.
