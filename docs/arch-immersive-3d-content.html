Data flow

Source of truth remains the completion_events log (owner-scoped via RLS).

  • completion_events → lit stars: course_id + lesson_slug on lesson rows feed buildConstellation (src/lib/sky.ts) → ConstellationState.stars[].lit; the on-course SeriesScene draws lit stars ignited and the current slug pulses cyan.
  • course → constellation: course_id aggregation → ConstellationState.complete / litStars; buildGalaxyModel maps each course to a 3D galaxy SECTOR.
  • blog-article stars (NEW, G1): event_type 'article' rows scatter free-floating ArticleStar[] in the galaxy interior, sourced in the model from the chronicle.
  • rank → illumination: lesson + course counts → deriveRank → RankId → RANK_ILLUMINATION (Starseed 0.10 → Celestial 1.00) drives overall galaxy luminance.

Performance strategy

  • Sprite stars, never individual meshes at scale. IgnitedStar renders 3 additive sprites per star — fine for the ~29-lesson tracker; galaxy caps sectors (~4-9 stars each) and 24 article stars. If a course exceeds ~60 stars, Points with per-point attributes is the scale-up path.
  • DPR cap 2: dpr={[1,2]}, powerPreference: 'high-performance'.
  • Lazy-load: the entire three/r3f chunk behind next/dynamic(..., { ssr: false }); blog pages never import three.
  • frameloop: render loop is cheap (sprite useFrame + damped lerps); add frameloop="demand" only if profiling shows a hot idle loop.
  • Reduced motion (G2): hook drives staticMode, skips ignition, disables drift/parallax, settles the camera. The tokens' media query zeroes DOM transitions + shimmer.

Bundle weight

three (~150-600KB gzipped) sits behind the dynamic import. Public entries ship a few-KB shell; the heavy r3f chunk loads only on /learn/[series] and /profile. Blog, home, hub, tags, search, and the certificate page stay three-free. The WebGL gate means no-WebGL clients download nothing extra (chunk never requested when the gate is false).
