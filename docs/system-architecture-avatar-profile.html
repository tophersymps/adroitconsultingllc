System Architecture — Avatar Menu + Profile/Settings

📅 August 11, 2026 📋 Adroit Blog 👤 Brainiac (Web Architect) 📄 v1.0

1. Component Architecture Overview

The signed-in account corner is a thin addition to the existing auth surface. Header remains the single auth-aware client component (reads useAuth()); the new AvatarMenu is a self-contained presentational + behavior component receiving user and onSignOut as props. The two account pages are server components gated server-side — no client auth flash, no duplicate /api/auth/session fetch.

  • Header.tsx (client, existing) — owns useAuth(), handleSignOut, mobile drawer state. Only the authControl block changes.
  • AvatarMenu.tsx (client, new) — 32px initials avatar trigger + 240px right-aligned role="menu" panel. Owns open/close, keyboard nav, outside-click, Escape, route-change close.
  • src/lib/avatar.ts (new) — pure functions initialsFromEmail() + avatarHueClass(); deterministic, shared by header avatar, dropdown identity header, and Profile page avatar.
  • /profile page (server, new) — session gate via getSupabaseServerClient() → redirect("/login?next=/profile") for guests; identity card (64px avatar, mono email, sign-in method) + stubbed Change password.
  • /settings page (server, new) — session gate; two sectioned cards, every control honestly stubbed with a visible COMING SOON badge.
  • globals.css — adds --shadow-menu, --shadow-dialog, --avatar-1..4 tokens to the Tailwind v4 @theme inline block.

Explicitly out of scope (future): ConfirmDialog component (no destructive API exists), password reset, clear-history, email-preferences toggle, avatar upload.

5. Schema Changes

  • None. No new tables, no altered tables, no auth schema changes. Reuses existing auth.users (Supabase) surfaced through the existing session endpoint.
  • No changes to src/lib/hooks/useAuth.ts interface (AuthUser { id, email }), no changes to src/shared/contracts.ts (quiz-tiers scoped).
