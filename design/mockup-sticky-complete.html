Completion control in the sticky audio bar

The lesson audio bar gains one terminal action: Mark complete. It is a quiet outlined button in the header row — never a second primary, never a second write path. Once the lesson is complete the control becomes a static “Completed” chip and stops being interactive; un-marking stays on the hero control above the article.

5State matrix

Six states, no seventh. There is no error state in the control: the write is optimistic through the existing hook, and a failed write simply leaves the button in place.

default

Outlined, navy label. 44 × 44 minimum, 10px radius — reads as an action, not a second CTA.

hover

Border darkens to rgba(11,29,58,.42), surface sinks one step. No lift, no shadow — it is inside someone else’s card.

focus-visible

Site convention: 2px red, 2px offset. Never removed; keyboard reachable between Speed and the article.

pressed

Fill to --line for the duration of the press. Instant, no scale — a scale would fight the sticky bar’s own shadow transition.

hydrating

disabled + 45% opacity while the hook resolves completion. Label unchanged — no spinner in a 44px target.

complete

Static chip. 113×30 inside the same 143×44 slot, emerald, cursor:default, no hover, no toggle. tabindex="-1" — focus moves here on the swap so a keyboard user is not dropped to <body>, but it never enters the tab order.
