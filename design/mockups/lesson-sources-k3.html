Keeping architecture documentation alive

MS Michael ShawOct 24, 20269 min read

Why documentation rots

Architecture documents fail for a boring reason: nobody owns the second revision. The first draft is written with genuine care, then the system moves and the page does not.1 Within two quarters the diagram describes a system that no longer exists.

Salesforce orgs make this worse than most platforms. Declarative change is cheap, so the shape of an org drifts weekly while the document stays a quarterly artefact. Metadata API comparisons catch drift in objects; they do not catch drift in intent.2

A review loop that survives release

The fix is not more documents. It is a single living page, reviewed on the same cadence as the release, with an explicit owner and a visible "last verified" date.3 Anything that cannot be verified in ten minutes is deleted, not archived.
