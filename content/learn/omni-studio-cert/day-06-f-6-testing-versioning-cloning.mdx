## Deep Dive

**Testing:** validate each component's behavior against requirements with realistic test data. Use debug mode (OmniScript), the Debug Console (request/response logs), and the OmniStudio testing framework; test the happy path AND error/empty states.

**Versioning:** OmniStudio components carry versions; you can snapshot, retrieve, and deploy specific versions. Version control (git) treats component JSON as source files. Review diffs, tag releases, roll back.

**Cloning:** duplicate an existing component as a starting point for a variant (e.g., new loan product from an existing flow). Cloning preserves configuration that can be adjusted, which is far faster and safer than rebuilding.

**Publishing is separate from saving:** components must be published/activated for end users to see changes. 'Saved but not published' is the top reason users see old versions.

**Testing discipline:** create test data to validate component functionality or behavior; verify across channels and permission sets, not just as admin.

## Configuration Walkthrough

1. Save a component, then publish/activate it for users.
2. Clone a component from the OmniStudio UI to branch a variant.
3. Retrieve/commit versions to git; tag releases; deploy pinned versions.
4. Run component tests + debug console checks before promoting.

## Exam Traps

- **Equating save with publish:** they are separate steps.
- **Rebuilding from scratch** instead of cloning when a variant exists.
- **Testing only as System Administrator:** access layers hide real user issues.

## Exam Tip

Version = snapshot, Clone = branch, Publish = ship. Three verbs, three different actions.
