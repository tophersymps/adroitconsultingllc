## Deep Dive

**Data source options:** SOQL Query (simple, fast, but does *not* apply field-level security), SOSL Search (text search against the index), Data Mapper Extract (FLS-aware, transforms, parameterized), Integration Procedure (complex orchestrated data in one call), Apex Remote (Apex class implementing `VlocityOpenInterface`), Apex REST, REST (Named Credential or plain web endpoint), Streaming/Platform Event/PushTopic (event-driven data), and Custom (embedded sample JSON for prototyping).

**Cards loop records:** FlexCards loop over the records their data source returns. Each record renders as one card. A single-record source yields one card; a list yields many.

**Test JSON before layout:** preview the data source output, verify field names and nesting, then bind elements to those exact paths. Wrong JSON shape is the #1 cause of blank cards.

**Security judgment:** when field-level security matters (low-privilege users), choose Data Mapper over SOQL. Data Mappers fully support FLS.

**Custom JSON is a placeholder:** sample JSON is for prototyping. Replace it with a real source before publishing to production.

## Configuration Walkthrough

1. In the FlexCard editor, add a data source (SOQL / Data Mapper / Integration Procedure / etc.).
2. Preview the returned JSON: check the record shape, field names, and array nesting.
3. Adjust filters/parameters so the payload matches the intended card layout.
4. Swap the Custom JSON for a real source before publishing.

## Exam Traps

- Choosing SOQL when FLS is required. SOQL data sources bypass field-level security.
- Forgetting the card loops records. Designing a layout for one record when the source returns many.
- Building bindings before validating the JSON shape.

## Exam Tip

JSON first, layout second. Preview the payload, then bind to real field paths.
