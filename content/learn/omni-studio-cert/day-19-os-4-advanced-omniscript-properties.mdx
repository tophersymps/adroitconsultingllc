## Deep Dive

**Multi-language.** OmniScripts support translations, so labels and element text render per locale. Configure translation workbench entries for the script's elements, and the same script serves users in every language without a second definition.

**Save Options.** Draft, save-as, and auto-save patterns let users save their progress and resume later. This matters for partial applications, where a user starts a flow and comes back days later. Resume reloads the saved JSON back into the script so they pick up where they left off.

**Knowledge Articles.** Surface relevant help or knowledge content inside the flow itself. Users get guidance without leaving the OmniScript, which keeps the application path intact instead of forcing them to search elsewhere.

**Messaging Framework.** Send SMS and email from within the script using configured templates, triggered by actions. Typical use cases are a confirmation after submission or a follow-up to the applicant.

**Recognize the property.** These are feature-level configurations on the OmniScript, and the exam tests whether you can match a scenario to the right capability: translation, resume, notify, or help. Confusing them is the classic miss.

## Configuration Walkthrough

1. Multi-language: add translations for the script's labels.
2. Save Options: enable draft/save-as and map the resume entry point.
3. Knowledge: configure article association/display.
4. Messaging: configure templates and add a send action.

## Exam Traps

- Using Save Options when the requirement is translations (and vice versa).
- Assuming draft-save works without configuring the resume flow.
- Messaging configured but no template/send action, so nothing ever goes out.

## Exam Tip

Translate → multi-language. Resume → Save Options. Help → Knowledge. Notify → Messaging. Four flags, four scenarios.
