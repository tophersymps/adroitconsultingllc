## Deep Dive

**Child OmniScripts are reusable sub-processes.** Address capture, consent, payment: invoke the same child from any parent script. They modularize logic. Change it once, and every parent picks it up. Data passes parent to child via context, then merges back.

**FlexCards inside OmniScripts embed context.** A FlexCard is a display element within a step. Drop in an account summary or an eligibility card and show real-time data without leaving the flow.

**Custom LWCs handle what standard elements cannot.** Specialized pickers, maps, dashboards. When a standard input element cannot meet the UI requirement, embed an LWC as an element. It communicates with the OmniScript through its data contract.

**Complex UI configurations compose all three.** A single step may hold a FlexCard for context, an LWC for specialized input, and a child OmniScript launch for a nested process.

**The integration pattern is consistent.** Embed, exchange data, merge the results. Know what each embed type returns so downstream actions receive the right JSON.

## Configuration Walkthrough

1. For reuse: create a child OmniScript and invoke it with context from the parent.
2. For display: embed a FlexCard element bound to contextual data.
3. For custom UI: register and embed an LWC element.
4. Verify data flows back (child results, card data, LWC payloads).

## Exam Traps

- Duplicating sub-process steps instead of using child OmniScripts.
- Embedding a FlexCard that needs context you never pass.
- Assuming LWC data merges automatically. Wire its output to the script JSON.

## Practice Questions

**Q1.** Two OmniScripts both need to capture an address. What is the best approach?

A. Duplicate the steps in both<br/>
B. One child OmniScript invoked from both parents<br/>
C. An Apex trigger<br/>
D. A FlexCard

<details>
  <summary>Show answer</summary>
  **Correct: B.** Child OmniScripts modularize reusable sub-processes, so one change flows to every parent.
</details>

**Q2.** During a claim flow, the user should see a live account summary. What do you embed?

A. A FlexCard inside the OmniScript<br/>
B. A second OmniScript<br/>
C. A formula field<br/>
D. A report

<details>
  <summary>Show answer</summary>
  **Correct: A.** FlexCards embedded in OmniScripts provide contextual, real-time display inside the flow.
</details>

**Q3.** When can custom LWC elements be used in an OmniScript?

A. Never<br/>
B. When standard elements are insufficient for the UI requirement<br/>
C. Only on mobile<br/>
D. Only in test mode

<details>
  <summary>Show answer</summary>
  **Correct: B.** Custom LWCs extend the OmniScript UI when standard elements are not enough.
</details>

## Exam Tip

Reuse goes to a child OmniScript. Display goes to a FlexCard. Custom UI goes to an LWC. Compose all three for complex flows.
