## Deep Dive

**Event Listeners:** card-side subscriptions to events fired elsewhere (other cards, OmniScripts, the page), enabling refresh-on-change and cross-component coordination.

**Session Variables:** values shared across components within the session (e.g., logged-in user context), available to cards for display or conditions.

**Public Attributes:** the card's public API. The host page passes values IN (e.g., recordId, accountId) so the card renders in context. Essential for reuse across pages.

**Multi-language:** cards support translations so labels/values render per locale.

**Integration points:** embed a child FlexCard inside a parent card; launch/integrate with OmniScripts; embed custom LWCs as elements for UI beyond the standard set.

Together these make cards context-aware, coordinated, and embeddable: the difference between a static card and a real application component.

## Configuration Walkthrough

1. Define public attributes for context the host page passes in.
2. Add event listeners for coordination with other components.
3. Reference session variables in bindings/conditions.
4. Add translations for multi-language support.
5. Embed a child FlexCard or custom LWC where needed.

## Exam Traps

- Hardcoding context instead of using public attributes kills reuse.
- No listener for a fired event: coordination silently fails.
- Assuming session variables are available cross-session (they are session-scoped).

## Practice Questions

**Q1.** Which mechanism passes data from a host Lightning page INTO a FlexCard?

A. Public Attributes / Session Variables<br/>
B. A hardcoded JSON file<br/>
C. Platform Cache only<br/>
D. Reports

<details>
  <summary>Show answer</summary>
  **Correct: A.** Public attributes (and session variables) expose entry points for host context.
</details>

**Q2.** How does a card react to changes elsewhere on the page?

A. Event Listeners<br/>
B. A new data source<br/>
C. A Calculation Matrix<br/>
D. Manual refresh

<details>
  <summary>Show answer</summary>
  **Correct: A.** Event listeners subscribe to events and trigger card reactions.
</details>

**Q3.** Which advanced integration lets you nest one card inside another?

A. Child FlexCard<br/>
B. SOQL data source<br/>
C. Formula<br/>
D. Streaming API

<details>
  <summary>Show answer</summary>
  **Correct: A.** Child FlexCards nest inside parent cards for composed displays.
</details>

## Exam Tip

Public attributes = in, events/listeners = between, session variables = shared, translations = per locale.
