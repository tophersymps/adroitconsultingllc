## Deep Dive

**States drive card-level conditional rendering.** A card changes what it shows based on conditions. Common states: default, empty (no records), error (data source failure), and custom states (high-priority, overdue, approved). When a condition evaluates true, that state's layout renders.

**Conditions are expressions over card data.** They evaluate fields, expressions, and session variables. The state whose condition is true renders its layout. If more than one matches, the first matching state wins, so ordering matters.

**Element-level conditional rendering is separate.** You can show or hide an element, or alter its appearance (color, emphasis), based on a condition. This powers dynamic forms and alerts.

**Timing matters.** State evaluation happens on data load and on relevant events. A condition on a field that loads later may flash or never trigger, so verify against when the data actually arrives.

**Common bugs.** A condition that is never true (wrong field path or value type), a missing empty state (users see a blank card), and state ordering issues.

## Configuration Walkthrough

1. Add states (default, empty, error, custom) to the card.
2. Define conditions with expressions on card data.
3. Set element-level visibility and appearance conditions.
4. Test each state with representative data, including empty and error.

## Exam Traps

- Missing empty state, so users get a blank card on zero records.
- Condition compares a string to a number, a type mismatch that is never true.
- Testing only the happy path, so states fail silently on edge data.

## Practice Questions

**Q1.** A card must show "No records found" when the data source returns nothing. What do you use?

A. An empty state with a condition on record count<br/>
B. A second FlexCard<br/>
C. An OmniScript step<br/>
D. A Remote Action

<details>
  <summary>Show answer</summary>
  **Correct: A.** States enable conditional rendering; the empty state triggers on zero records.
</details>

**Q2.** A field should turn red when its value exceeds a threshold. Which mechanism handles that?

A. An element-level condition altering appearance<br/>
B. A repeater<br/>
C. A SOQL filter<br/>
D. A theme change

<details>
  <summary>Show answer</summary>
  **Correct: A.** Conditional rendering can alter element appearance based on conditions.
</details>

**Q3.** A custom state never displays even though the data looks right. What is the likely cause?

A. The condition doesn't match the actual data (path or type)<br/>
B. The theme is dark<br/>
C. The card has no data source<br/>
D. The page is in a Community

<details>
  <summary>Show answer</summary>
  **Correct: A.** Conditions must evaluate true against live data; mismatches block the state.
</details>

## Exam Tip

States handle card-level conditional rendering; element conditions work at the item level. Always build the empty state.
