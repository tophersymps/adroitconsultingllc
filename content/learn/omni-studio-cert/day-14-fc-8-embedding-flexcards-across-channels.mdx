## Deep Dive

**One card definition, many channels.** FlexCards embed on Lightning pages (App Builder), Experience Cloud sites (Communities), OmniScripts (as a contextual element), and mobile. You build the card once and drop it wherever it belongs.

**Channel context works differently.** Embedding on a record page passes record context automatically. Experience Cloud and mobile may need public attributes or session context configured. That extra setup is the main thing that trips people up.

**Reuse is the point.** Design the card with public attributes so the same card renders correctly on an internal console and a customer portal. If you hardcode context, you lose that.

**Channel constraints.** Experience Cloud needs the license. Data sources can behave differently per channel. Component behavior changes too: mobile touch targets, offline handling. None of these are free.

**LWC wrappers.** FlexCards auto-generate Lightning web component wrappers for use in App Builder and Experience Builder. That's how the drag-and-drop embedding works.

## Configuration Walkthrough

1. Design the card with public attributes for context.
2. Add the FlexCard LWC to a Lightning page (App Builder).
3. Add it to an Experience Cloud page (Experience Builder).
4. Embed inside an OmniScript or another card as needed.
5. Verify per channel (desktop, mobile, portal).

## Exam Traps

- Building for Lightning only, then discovering portal/mobile context gaps.
- Forgetting Experience Cloud licensing before promising a portal embed.
- Hardcoding record context instead of public attributes. This breaks reuse.

## Practice Questions

**Q1.** Which statement about embedding FlexCards is TRUE?

A. They only run on desktop Lightning pages<br/>
B. They embed across Lightning, Experience Cloud, OmniScripts, and mobile<br/>
C. They can't embed in OmniScripts<br/>
D. They require Apex to embed

<details>
  <summary>Show answer</summary>
  **Correct: B.** FlexCards are channel-agnostic: Lightning, Experience Cloud, OmniScript, mobile.
</details>

**Q2.** What makes the same FlexCard work on both an internal console and a customer portal?

A. Public attributes for context + per-channel verification<br/>
B. Two separate cards<br/>
C. A custom LWC<br/>
D. An Apex trigger

<details>
  <summary>Show answer</summary>
  **Correct: A.** Public attributes make cards context-driven and reusable across channels.
</details>

**Q3.** What does a FlexCard auto-generate for App Builder / Experience Builder embedding?

A. An LWC wrapper<br/>
B. An Apex class<br/>
C. A Flow<br/>
D. A report

<details>
  <summary>Show answer</summary>
  **Correct: A.** FlexCards generate LWC wrappers for drag-and-drop embedding.
</details>

## Exam Tip

Design for context (public attributes), then embed everywhere. Verify each channel. They're not identical.
