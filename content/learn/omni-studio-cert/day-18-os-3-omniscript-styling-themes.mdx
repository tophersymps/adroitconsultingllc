## Deep Dive

**Themes vs element styling.** OmniScript appearance is controlled by themes (shared, applied to many scripts) and element-level styling (per-element overrides). Themes set the system; element styling handles the exceptions.

**What a theme defines.** Themes define the design system: colors, fonts, button styles, and spacing. They apply consistently across OmniScripts and are often shared with FlexCards for a unified brand.

**Element-level styling.** Element-level styling customizes individual elements (an emphasized field, a highlighted section). Use it sparingly so the theme stays authoritative.

**Responsive behavior matters.** The same OmniScript renders on desktop, tablet, and mobile. Test layouts at each width.

**Branding consistency is the exam-relevant theme.** Recognize when a scenario calls for a theme vs an inline tweak.

## Configuration Walkthrough

1. Apply a theme to the OmniScript.
2. Override specific element styles where needed.
3. Preview at desktop + mobile widths.

## Exam Traps

- Inline-styling everything. Theme drift and maintenance pain.
- Ignoring mobile rendering of complex steps.
- Applying styles to elements the theme already covers (redundant).

A. A shared theme<br/>

A. Element-level styling<br/>
B. A new theme per field<br/>
C. Hardcoded colors<br/>
D. A FlexCard

<details>
  <summary>Show answer</summary>
  **Correct: A.** Inline element styles handle one-off exceptions to the theme.
