## Deep Dive

**Single-level card:** one record per card, flat fields (name, account number, status) laid out in the card body.

**Multi-level card:** nested data structures (e.g., an Account card that also shows related Cases or line items). Nesting comes from the data source (related records) and is rendered with repeaters.

**Repeaters** iterate over an `ARRAY` inside a record's JSON (e.g., `Cases` array) and render repeated elements for each item. They are the mechanism for lists-within-cards.

**Layout:** the FlexCard editor organizes elements on a 12-column grid; elements span configurable widths; columns/sections group content. Widths are responsive across devices.

**Design for data shape:** if the source returns a nested array, the layout needs a repeater bound to that array path; missing repeaters = missing nested content.

## Configuration Walkthrough

1. Add a data source and preview its JSON (note nested arrays).
2. Drop elements onto the 12-column grid; set widths for the layout.
3. For nested lists, add a repeater bound to the array path.
4. Bind repeater child elements to item fields.

## Exam Traps

- Binding a repeater to an object instead of an array. It won't iterate.
- Forgetting widths on mobile. That leaves cramped single-column layouts.
- Treating multi-level as 'two cards'. It's nesting within one card via repeaters.

## Exam Tip

Array inside the JSON → repeater. Repeaters are how multi-level cards happen.
