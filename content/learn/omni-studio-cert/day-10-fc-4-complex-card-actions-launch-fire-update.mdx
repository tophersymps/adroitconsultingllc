## Deep Dive

**Actions make a card DO something:** launch an OmniScript (passing record context like Id and attributes), open a flyout (drill-down detail), fire events (custom/platform/pubsub), navigate, or update other components on the page.

**Launching an OmniScript** from a card action passes context so the flow opens pre-populated for the selected record: the standard 'act on this record' pattern.

**Events are the communication bus:** a card fires an event (e.g., 'record updated'), and other cards/components with event listeners react (refresh, change state, update data).

**Updating other components:** via event → listener, or direct component updates where the platform supports it. This is card-to-card coordination without code.

**Action parameters carry the data:** which record, which values, which navigation target. Configure parameters precisely: a missing Id breaks the downstream flow.

## Configuration Walkthrough

1. Select a button/link element in the card.
2. Add an action: Launch OmniScript / Fire Event / Flyout / Update component.
3. Configure parameters: record Id, attribute values, event name, payload.
4. On the receiving side, add an event listener to react.

## Exam Traps

- Firing an event with no listener anywhere: the event is lost.
- Launching an OmniScript without passing the record Id: the flow opens empty.
- Using actions for static links when a simple URL would do.

## Practice Questions

**Q1.** How does a FlexCard launch a guided process in context of the selected record?

A. Action → Launch OmniScript, passing the record Id/context<br/>
B. Apex trigger<br/>
C. URL redirect only<br/>
D. Cloning the card

<details>
  <summary>Show answer</summary>
  **Correct: A.** Card Actions launch OmniScripts with context so the flow opens pre-populated.
</details>

**Q2.** Card A must refresh when Card B saves data. What do you configure?

A. Card A fires no event; Card B listens<br/>
B. Card B fires an event; Card A has an event listener that refreshes<br/>
C. A second data source<br/>
D. Platform Cache only

<details>
  <summary>Show answer</summary>
  **Correct: B.** Events + listeners coordinate cards: fire on change, listen and react on the other side.
</details>

**Q3.** What carries the data when a card action launches an OmniScript?

A. Action parameters (record Id, attributes)<br/>
B. The card's theme<br/>
C. The browser URL<br/>
D. A hardcoded file

<details>
  <summary>Show answer</summary>
  **Correct: A.** Action parameters define what context the launched flow receives.
</details>

## Exam Tip

Actions = outbound (launch, fire, navigate). Listeners = inbound (react). Pair them for card-to-card coordination.
