Lesson 6 made your handoffs legible. You ask a tool to return its answer in a fixed, labeled shape, JSON pairs and lists, so the next step reads it without guessing. That lesson fixed the shape of the answer. This lesson fixes the shape of the question, and the move is the same in spirit: decide the fixed parts once, keep only the few genuinely variable parts fresh.

Here is the problem worth solving. You have a task you do every week. The task is the same task each time: same goal, same audience, same output format, same constraints. Only a handful of specifics change, the project name, the numbers, the dates, the person you are writing for. If you write a fresh prompt from scratch every week, you are re-deciding the same frame, the same instructions, the same format, over and over. That is the exact waste this course has been hunting since Lesson 2. A template is the cure: one prompt, written once, with blank slots where the fresh specifics go.

## What a parameterized prompt is

A parameterized prompt is a prompt with a fixed structure and a small number of named variable slots. The structure, the instructions, the role, the output format, the tone, stays the same every time you use it. The slots are the only parts that change, and you fill them with the new material for that run. The word parameterized just means the prompt has parameters, placeholders you supply values for.

Think of it the way you think of a form. A form has fields printed on it: name, date, department. The form is the same form for everyone; the fields are what make each filled-in copy specific. A template prompt is the same idea. You build the form once, then each week you fill in the blanks instead of printing a brand new form.

Here is the smallest honest example. The fixed part of a template looks like this:

> You are a careful data reviewer. Below the line is this week's numbers. Check them against the target, flag any number more than 10% off, and give me a one-paragraph explanation of each flag and what it suggests. Do not invent numbers.

Then comes the variable part, the slot that changes each run:

> ---
> This week's numbers: [paste the numbers here]

The prompt before the divider never changes. The slot after it does. That is the whole mechanism, and it is worth sitting with how little it is. A template is not a fancy feature. It is a decision about what stays fixed and what gets filled in, written down once instead of re-decided every time.

## Why the frame matters more than the filling

The value of a template is mostly in the fixed part, and people get this backwards. They assume the work is the filling, the fresh specifics. It is not. The work is the frame, and a good frame is why the output is consistent run after run.

Compare two people. Both ask a tool to turn weekly sales numbers into a one-page summary for their manager. The first person writes the whole request from scratch each week, describing the job, the audience, the format, the tone, in whatever words come out that Monday. The second person has a template whose frame is stable: same role, same output structure, same tone, same length, same label for where the numbers go. Only the numbers change.

The first person gets a different-shaped answer every week because the instruction changed every week. One week the summary is a paragraph, the next it is bullet points, one week it says "the numbers look good" and the next it buries the warning mid-sentence. The person has to re-read and re-sort the output every single time. The second person gets the same shape every week, a manager can scan it in thirty seconds, and the person's only real job is checking the numbers inside it. Same task, same tool, wildly different experience. The difference is entirely the frame, and the frame is built once.

## The slots are the only part that should change

Anthropic's prompting guidance makes the underlying point directly: clear, explicit instructions produce better results, and the golden rule is to show a prompt to a colleague with minimal context and ask them to follow it, because if they would be confused, the model will be too. [^1] A template lets you write that clear, complete instruction once, when you are not rushing, and then reuse the clarity instead of improvising it weekly.

## The slots are the only part that should change

The skill of building a template is deciding which parts are fixed and which parts are slots. Get this wrong and the template stops being a template. Too many slots and you have effectively rewritten the prompt each time, just with extra brackets. Too few and the template cannot stretch to cover the variations your task actually hits.

Start by asking what is genuinely different between one run and the next. For a recurring status update, the diffs are usually the facts: the period, the numbers, the blocking items, maybe the audience if the report goes to different people. Everything else, the role, the format, the tone, the length, the review criteria, is the same and belongs in the fixed part. The Anthropic guide offers a concrete way to keep the two apart: structure a prompt so the instructions, the context, and the variable input are each clearly marked, often with tags, which reduces the chance the model misreads a slot as part of the instruction. [^1] Marking the variable input as a slot instead of leaving it floating in the sentence is not cosmetics. It tells the model what is a rule and what is tonight's data.

Name each slot so its contents are obvious. A slot named [project] tells you and the model what belongs there. A slot named [numbers] or [this week's update] is self-explanatory. Keep slots to the handful that actually vary. Every slot you add is something you must supply with real, accurate material on every run, and a slot you leave empty is a slot where the model has to guess. Fewer, well-named slots beat a sprawling form.

## A worked example: Nadia stops rewriting her weekly client brief

Nadia writes a one-page engagement brief for her biggest client every Monday. The brief carries the same structure every week: what shipped, what is blocked, what is needed from the client, and one highlight worth celebrating. The audience, a senior sponsor who reads fast, never changes. The tone, plain and direct, never changes. The length, one page, never changes. What changes weekly is the substance: the shipped items, the blocker, the ask, the highlight.

Before she built a template, Nadia opened a fresh chat every Monday and described the whole job again. Her prompt drifted. Some weeks she remembered to name the four sections, some weeks she forgot the sponsor-reads-fast note, some weeks she let the tool run long. The briefs came back different shapes, and she spent her Monday rewrites fixing formatting the tool had gotten wrong because the instruction had been vague. The frame was being re-decided from scratch under time pressure, and time pressure is exactly when a frame gets decided badly.

Her template fixed the frame once, on a slow Thursday afternoon, and left four slots:

> You are the writer for a senior client sponsor who reads fast and wants plain, direct language. Produce a one-page brief with exactly four sections in this order: What shipped, What is blocked, What we need from you, and One highlight. Keep each section to a few bullets. Lead with the most important item. Do not invent anything, and if a section has nothing to say, write "none" rather than padding.
>
> Fill these slots with this week's facts:
> [what shipped]
> [what is blocked]
> [what we need]
> [this week's highlight]

Now Monday looks different. Nadia pastes four short lists into the slots, and the tool returns a brief in the exact shape the sponsor already knows how to read. The review stays, and this is where it should live: she checks that the shipped items are real, that the blocker is current, that nothing got padded. She is not re-negotiating format, because the format was decided once. The consistency is not a nice-to-have. It is the entire reason the sponsor can scan the brief in thirty seconds, and it is why a template that locks the frame down is worth owning.

That is the through-line from Lesson 6. There, you fixed the shape of the answer so a downstream tool could read it. Here, you fix the shape of the question so a recurring task comes back the same way every time. Same instinct, one level up the workflow. And the same honesty applies: a template does not remove the human's judgment, it concentrates that judgment where it counts, on the substance, the review, the decision, instead of on re-describing the job.

## When a template is the wrong tool

A template is not the answer to every recurring task, and naming the boundary is part of the skill. The trade is really about whether the fixed frame will actually get used. A template earns its keep when two things are both true: the task recurs often enough that the setup pays for itself, and the frame is genuinely stable across those recurrences.

If a task happens once, a template is ceremony with no payoff. You spent the effort building a form for a form you will never fill again. If the task recurs but its shape changes every time, a template is a straitjacket; the cuts did not survive contact with the material, and you spend your fill-in mentally rewriting the frame anyway. And if the task needs judgment that varies run to run, forcing it into a fixed frame makes the output rigid where it should be argued.

In the AI at Work primer, the judgment of how closely you review a tool's draft depends on how much is riding on the output. [^6] The same principle applies to templates. A low-stakes, high-frequency task with a stable shape is a template's natural home. A high-stakes, judgment-heavy, irregular task is not, and wedging it into a frame does not make it more reliable, it makes it harder to review. The lesson that comes next in this series digs into exactly this choice, deciding which tasks are worth owning a workflow for at all. For now, the honest test is a single question: will I run this same framed task again next week, and is the frame the same next week? If yes, build the template. If not, write the prompt and move on.

## Try it

Give yourself twenty minutes and build one template for a task you actually do on a schedule. The goal is not a perfect prompt. It is the experience of separating fixed frame from variable slots for a real piece of your work.

Step one, name the task. Pick something you do weekly or monthly with the same shape: a status update, a meeting brief, a summary for a manager, a response to a recurring kind of request. If you can borrow from the audit you ran in Lesson 2, use that.

Step two, write the fixed frame. Describe the role, the audience, the output format, the tone, and the review criteria, the parts that do not change. Write it once, completely, as if you had all the time in the world, because on the day you actually run it you will not.

Step three, name the slots. List the parts that genuinely change each run and give each a bracket name: [period], [numbers], [blocker], [highlight]. Keep the list to the handful that really vary.

Step four, paste the fresh material in and run it. The prompt below is a skeleton you can adapt to your task:

> Act as [your role here]. Produce [your output, e.g. a one-page status update] for [your audience]. Use [tone] language and keep it to [your length and format]. Cover exactly these sections: [section 1], [section 2], [section 3]. Do not invent facts, and write "none" rather than padding any section.
>
> Below is this week's material. Fill the slots with it and produce the output:
> ---
> [section 1 material]
> [section 2 material]
> [section 3 material]

Then read the output twice. First for substance, are the facts right, is nothing invented, is the most important item up top, the review you would apply to any draft. [^6] Then read for frame, did it hold the shape you asked for, were the slots treated as today's data and not re-decided instructions. A frame that holds shape run after run is the thing a template buys you, and now you know how to build one.

*Note: a parameterized prompt is a general pattern, not tied to any one vendor. The marker you use for slots, double brackets, a divider line, a tag, or a labeled section, varies by tool and by taste, and different chat tools expose different ways to save and reuse prompts. Use the tool you already have, match the pattern to what it offers today, and treat your company's data and acceptable-use policies as the binding rules. The transferable part is the decision about what stays fixed and what gets filled in, a decision you make once and then stop making.*
