# Lesson 47: Activation Targets and Setup: What an Activation Is and Connecting a Destination

A consultant finishes a segment that is exactly what the campaign team asked for, then tries to send it to Google Ads and finds the destination is not in the list. She spends an afternoon rebuilding filters before someone points out that the audience was never the problem. The activation path was wrong: no target had been created for the advertising platform, and she was about to learn that some segment types cannot be published to an activation target at all.

Requirement ac-3a, in the Data Activations and Utilization domain worth 20% of the Salesforce Data 360 Consultant exam, asks you to publish activations within Data 360, starting with what an activation is, the activation targets available, and configuring a target and its marketing or advertising destination. This lesson defines the two part job of creating an activation, surveys the target families and what each one accepts, and walks a finished segment to a live destination.

The order to build in is backward from the destination. Confirm where the audience is going, confirm that the target type supports your segment type and publish cadence, create the target, and only then attach the segment. Design backward and you avoid the afternoon the opening describes.

## Deep Dive

### An activation connects a segment to a destination, and the target holds the credentials

An activation is the connection between a segment and a destination. The segment decides who is in the audience; the activation decides where those members go and how often. Activation itself is the process that publishes a segment to your activation platforms, and an activation target is used to store authentication and authorization information for a given activation platform, such as Marketing Cloud Engagement or Meta.[^1]

That split defines the job. Creating an activation is a two part task: define the target once, then attach your segment and activation details to it. Once a target exists, you can publish segments to it with contact points and additional attributes, which is what powers personalized marketing, advertising audiences, and consistent customer experiences.[^1] A consultant who needs to send an audience to an advertising platform such as Google Ads must create an activation target first, because the target holds the credentials and configuration for the destination. What she must create first is an activation target that stores the platform authentication and authorization information for the advertising platform.

There is a state prerequisite that catches people. An activation only works when its segment is active or published. The help for Marketing Cloud Engagement activation states the rule directly: make sure the segment you want to activate is in an active or published state, and if you create an activation with a segment in a processing state, it can remain in an error state until the segment finishes processing.[^2] Activate from a segment that has finished, and the activation starts on solid ground.

A related design point is ownership. Because the target stores the credentials and the activation carries the delivery rules, two different people often own the two halves: an administrator owns the target and its connection, and a marketer owns the activation and its attributes. Agreeing on that split before you build keeps an expired credential from looking like a broken audience, and it keeps a campaign change from quietly altering shared infrastructure. When activation stops working, the first question is which half changed.

### Several target families cover marketing, storage, commerce, loyalty, and advertising

Data 360 supports several activation target families, and naming them by what they receive is the fastest way to remember them. Marketing Cloud Engagement and Marketing Cloud Personalization (formerly Interaction Studio) receive audiences into marketing platforms. File storage targets such as Amazon S3, SFTP, Google Cloud Storage, and Microsoft Azure write the audience as files. B2C Commerce and Data 360 Loyalty are platform destinations, and a Data 360 target publishes to the Audience DMO for access without a direct connection to an external system. External activation platforms cover advertising networks such as Google Ads, Meta, LinkedIn, Amazon Ads, and Snapchat.[^3]

Each family carries its own constraints, so the target choice often determines which segment types and publish schedules are even possible. An external platform can have multiple activation targets, but you can attach only one activation target to an external platform account, which is a governance detail worth knowing before several teams create targets for the same ad account.[^4] Deleting a target applies to all segments using it, so a target is shared infrastructure rather than a private setting.[^3]

The practical consequence is that the target is not a formality at the end of the build. It is a design decision at the start. Choose the target family first, and let its constraints shape the segment type and the schedule, rather than building the audience and then discovering the destination cannot accept it.

File storage targets deserve their own note, because they are how an audience leaves Data 360 for a system that is not a marketing platform. A file target writes the audience as files to Amazon S3, SFTP, Google Cloud Storage, or Microsoft Azure, which is the pattern for feeding a data warehouse, a homegrown scoring job, or a partner that reads flat files rather than an API.[^3] The same audience that feeds a marketing journey can feed a warehouse through a second activation to a file target, so one segment can serve two very different consumers. When a requirement puts the audience in a warehouse rather than an inbox, the file storage target is usually the answer.

### Not every activation type can reach every target

The compatibility matrix is the part of this objective most likely to be tested, so learn it as a table rather than a paragraph. A standard segment on a standard publish, at 12 or 24 hours, supports destinations including Marketing Cloud Engagement, Marketing Cloud Personalization, file storage, B2C Commerce, Data 360 Loyalty, Data 360, and external advertising platforms such as Google Ads and Meta.[^5] The same standard segment on a rapid publish, at 1 or 4 hours, supports a narrower set: Marketing Cloud Engagement, file storage, and Data 360.[^5]

The exclusions matter as much as the inclusions. A dynamic segment cannot be published to an activation target at all; dynamic segments run by API call only.[^5] A real-time segment serves only the real-time data graph.[^5] Waterfall segments, by contrast, follow the wider standard publish path with access to the same broad set of targets.[^5]

Learning this matrix prevents the worst design failure in this domain, which is building an audience that no destination can accept. When the scenario names a segment type and a destination, the question is often simply whether the pair is on the same compatibility row. If a requirement calls for a dynamic segment and a marketing destination, the honest answer is that the dynamic segment cannot be scheduled or published, and the requirement needs a standard or waterfall segment instead.

A second compatibility trap is cadence. A consultant may pick rapid publish to get a fresher audience into an advertising platform and then find that the rapid row lists only Marketing Cloud Engagement, file storage, and Data 360.[^5] The freshness the business asked for and the destination it named can be mutually exclusive, and the fix is to change one of the pair rather than to force it. Read the compatibility table with both the destination and the desired cadence in hand, and the conflict surfaces before the build does.

### You create a target on the Activation Targets tab

Creating a target is a short, repeatable task, and Marketing Cloud Engagement is the clearest example to learn because its extra steps generalize. To create an MCE target you open the Activation Targets tab and click New, select Marketing Cloud Engagement, and name it. Then you select the data space to associate with the target, choose the Marketing Cloud connection, include the business units that receive the published segments, and save the target.[^6] Creating an activation target requires an activation focused permission set such as Data Cloud Architect or Data Cloud Activation Manager.[^6]

A few details reward attention. The target name has a length limit and a list of disallowed characters, so a naming convention is easier than an ad hoc name.[^6] When a target has multiple business units, the activation filters contacts by those business units and the segment activates as a shared data extension rather than a plain data extension, so a multi-BU target behaves differently from a single-BU target.[^6] That is why a well named, well documented target shared across campaigns is better than a new target per campaign.

Treat the target as shared infrastructure. One correct target can serve many activations, and naming it by destination and purpose, rather than by the first campaign that used it, saves the next consultant from guessing which of three similar targets is the right one.

Permission and data space belong in this step too. Creating a target needs an activation focused permission set such as Data Cloud Architect or Data Cloud Activation Manager, and the target is associated with a data space when you create it.[^6] If the target's data space does not match the segment's, the activation cannot see the audience it is meant to deliver. Choosing the data space deliberately at creation, rather than accepting the default, is what keeps the target usable by the team that owns the audience.

### You wire a segment to a destination by creating the activation

With the target in place, wiring the segment is the second half of the job. You open the segment, go to Activations, and click New, then select the activation target. You choose the activation membership data model object, such as Individual or Unified Individual, and continue.[^2] Then you select the contact points to include, such as email or phone, and set their source priority. You can add attributes beyond the defaults, including related attributes reached by a path from the activated on object, and you save.[^2]

What happens on save is the useful part. The segment publishes on the next scheduled publish for the target, and on the first publish, if the activation count is greater than zero, a data extension is created at the destination and the segment records are added to it.[^2] Every later publish updates that destination object with the records currently in the segment, and the records from the previous activation are removed, so the destination reflects the most recent successful activation rather than an accumulating pile.[^2] Activation also includes only known profiles, so anonymous profiles within the segment are excluded from the final audience.[^2]

Understanding this removes a class of support ticket. If the first publish produced no data extension, the most likely reason is that the activation count was zero, not that the integration is broken. Check the count before you suspect the connection.

### Contact points and their source priority decide who the destination can reach

Contact points are how the destination can actually reach a person. Contact point selection determines which objects and fields are included in an activation and are sent to an activation target, and the source priority order determines which contact point value is selected for the activation.[^7] Marketing Cloud Engagement is often selected by default for the email contact point, and the default source priority for MCE places MCE as the first source and then an Any source and Any type.[^7]

Priority order matters when several sources supply an email or a phone, because the activation sends the value from the higher priority source. Leaving the broad entries in place lets the activation introduce contacts from other sources, which may be exactly what you want or may be a governance problem. To prevent the activation from introducing new contacts to Marketing Cloud Engagement from other sources, you remove Any Source and Any Type from the source priority, and to allow it you keep them.[^2] Expect the activation population to be lower when you select values from fewer sources, because the contact point filter is doing real work.[^7]

Setting priority deliberately is part of activation design, not an afterthought. A consultant who leaves the defaults and later discovers the campaign reached contacts from an unintended source has found the difference between a configured activation and a correct one.

## Config Walkthrough

Wiring a destination is a six step sequence once the target exists.

1. In the Data 360 app, open the Activation Targets tab and click New.
2. Select the target type, such as Marketing Cloud Engagement or an external advertising platform, then click Next.
3. Name the target uniquely, select the data space, and complete the connection details. For Marketing Cloud Engagement, choose the Marketing Cloud connection and the business units.[^6]
4. Save the target, then open the segment you want to deliver, go to Activations, and click New.
5. Select the activation target, choose the activation membership data model object, configure contact points and their source priority, then add any extra or related attributes.[^2]
6. Save the activation. The segment publishes on the target's next scheduled publish, and the first publish with a count above zero creates the destination object.[^2]

## Try it

Take a destination and reverse the build. Name the target family, then check the compatibility row for your segment type and publish cadence, then confirm the target can be created with the permission set you have and the data space you need. Only after those three pass would you open the segment and click New under Activations. If the pair is not on the same compatibility row, stop and fix the segment type before you spend time on contact points and attributes.

## Exam Traps

Three traps dominate this objective.

First, assuming any segment type can reach any target. Compatibility is constrained. A dynamic segment cannot publish to an activation target, and a rapid publish supports fewer destinations than a standard publish, so the pair matters before the audience does.

Second, creating the activation while the segment is still processing. An activation created on a processing segment can sit in an error state until the segment finishes, so activate from an active or published segment.

Third, leaving contact point source priority at its default. Broad any source or any type entries can let the activation introduce contacts from sources you did not intend, which is a governance risk rather than a convenience.

## Decision rules to carry forward

Design backward from the destination. Name the target family, confirm the segment type and publish cadence are compatible with it, create the target once with the right permission set and data space, and then attach the segment. Remember that the target stores the credentials and configuration, so nothing reaches an advertising platform until its target exists. Activate only from an active or published segment, because a processing segment leaves the activation in an error state. Set contact point source priority on purpose, and decide whether the activation may introduce contacts from other sources. Keep targets shared and well named, because one good target serves many activations and a deleted target takes every segment using it with it.
