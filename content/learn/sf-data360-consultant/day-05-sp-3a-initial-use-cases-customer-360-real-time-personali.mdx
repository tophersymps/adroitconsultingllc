# Lesson 5: Initial Use Cases: Customer 360, Real-Time Personalization, and Next Best Action

A company buys Data 360, connects six sources, and proudly reports that everything is "in the platform." Then a service rep opens a customer record and still does not see the support history that lives in a second system, because the records were ingested but never unified. The data is present and the profile is not. That gap is the failure this lesson exists to prevent, and it is the most common reason an early use case stalls: everything downstream, from personalization to segmentation, reads from a unified profile that does not exist yet.

The requirement behind this lesson is sp-3a: "Identify initial use cases for Data 360, covering the highest-value starting patterns (Customer 360 unified profiles, real-time personalization, and next best action)." It sits in the Solution Positioning domain, which is 14% of the Salesforce Certified Data 360 Consultant exam. This is the requirement where the exam tests whether you can match a business situation to the right Data 360 pattern and recognize the prerequisite that gates them all.

This lesson walks the five starting patterns a consultant should know cold, in the order a real engagement usually stacks them: Customer 360 as the foundation, real-time personalization as the headline, next best action and next best offer as the decision layer, segmentation and activation as the action layer, cross-cloud insights as the differentiator, and enrichment as the low-friction start. It closes with the prerequisite that, if it is missing, makes every one of those patterns fail.

## Deep Dive

### Customer 360 is the most common first use case, and the foundation for the rest

Customer 360 is the pattern of unifying records from CRM and external systems into one profile so that sales, service, and marketing all see the same customer. The value is immediate and visible, because an agent opens a record and sees full cross-channel history instead of guessing which system holds the truth. It is also the pattern that proves the hardest capability in the platform, identity resolution, early, which is why consultants usually position Customer 360 as the foundation use case rather than an advanced one. Every other use case, from personalization to analytics, consumes the unified profile it produces.

It helps to be precise about what "unified" actually means. Identity resolution is the processing engine that generates unified profiles from source profile data stored in Data 360, and it works through a ruleset that contains match rules and reconciliation rules. Match rules decide which source profiles belong to the same person; reconciliation rules decide which single value displays when sources disagree, for example via last updated, most frequent, or source sequence. A unified profile is not a golden record and identity resolution is not a master data management system. It links records and reconciles what displays without overwriting the underlying source objects, and each unified profile keeps every unique contact point value from every source.[^1]

Here is how the exam tends to ask it. A service team wants an agent to see the customer's full cross-channel history on the service console record. The question is not "which insight should we build" but "which use case is this." The answer is a unified Customer 360 profile surfaced in the console. A lifetime value insight is a component you could add later, and advertising suppression is a different objective entirely. When the scenario is about one agent seeing one customer's whole story in one place, it is the Customer 360 profile use case.

### Real-time personalization is the headline use case

Real-time personalization is the pattern that reacts within a session. Data 360's real-time layer processes events such as web and mobile clickstreams, visits, cart activity, and checkouts, and it does so at a latency measured in milliseconds. Three capabilities carry it: real-time identity resolution merges profiles across devices so an unknown visitor becomes a known one mid-session, real-time insights compute scores such as visit history or lifetime value on the spot, and real-time actions respond while the visitor is still on the page. The output feeds personalization and offers on web, mobile, chat, or in the hands of a service agent.[^5]

The insight types are not interchangeable, and the exam likes the distinction. A calculated insight is a batch computation over your stored data that can create metrics at the profile, segment, and population levels, and it can be authored in SQL or the Visual Builder. A streaming insight is an aggregation query over a rolling time window on streaming data, with windows as small as one minute, but segment and activation do not support streaming insights. A real-time insight runs in real time with results in milliseconds and requires a real-time data graph, because Data 360 calculates and stores the insight in that graph. So a question about a score computed from a single record to drive in-session personalization points at a real-time insight, while a question about a nightly metric for a report points at a calculated insight.[^2]

When the scenario is in-session, the capability set to reach for is real-time identity resolution, real-time calculated insights, and real-time actions. A retailer that wants to recommend products based on a shopper's browsing and cart events within the same session cannot get there with a nightly batch run. The strongest distractor, batch segmentation activated to email, is real and useful, but it is far too slow for a decision that has to land before the shopper leaves the page. Real-time is the answer precisely when the decision happens in the moment.

### Next best action and next best offer turn data into guidance

Next best action and next best offer take prediction a step further: instead of a score on a record, they produce guidance about what to do or show next. They combine predictive scores and calculated insights with real-time context, so the system recommends the best next step whether the customer is in a sales console, a service console, or a digital experience. On the Salesforce side, Einstein Next Best Action recommends actions to users through flows and strategies built on the Recommendation object, and Personalization's Einstein Decisions is the machine learning approach for next-best-offer decisioning on a website. In every case the recommendation is grounded in the unified, real-time profile.

The mechanism that makes in-session decisioning fast enough is the real-time data graph. In-session decisioning, such as a next best action query when an agent opens a record, depends on the real-time data graph, because the graph pre-joins a profile with its related data so the decision can be computed without assembling the data on the fly. Salesforce Personalization uses the real-time profile from Data 360 for the same reason: to ensure every decision is contextual and relevant to what the customer is doing right now.[^3]

The business value is straightforward and worth stating in the terms a stakeholder uses. Higher conversion, higher retention, and less guesswork in the moment. A rep who is told the single best next step on a renewal closes more than a rep staring at a dashboard. But the value only lands if the recommendation is specific and timely, which is why next best action belongs after Customer 360 and the real-time layer are in place, not before. Skip the foundation and the recommendation is generic.

### Segmentation and activation are the action layer

Segmentation and activation turn a unified profile into an actioned audience. A segment is built on unified profiles using direct and related attributes, and it is published, or activated, to destinations such as Marketing Cloud, ad platforms, or other channels. Activation is the process that publishes a segment to your activation platforms, and an activation target stores the authentication and authorization information for a destination such as Marketing Cloud Engagement or Meta. Once a target exists, you publish segments with contact points and additional attributes to it.[^4]

Because segments read from the unified profile, a scenario that asks for a targeted audience always depends on identity resolution being in place first. This is why consultants sequence unification ahead of segmentation: you cannot segment a customer you have not yet recognized. Two more details matter operationally. Activation supports both streaming and batch delivery, chosen for the use case and the destination, and it offers full refresh, which updates all records, or incremental refresh, which publishes only records added, updated, or deleted since the last successful run. Naming the refresh type in a design conversation is how you control cost and latency.

The reason segmentation and activation are foundational is that they close the loop. A unified profile with no activation is inventory; a unified profile that feeds a live campaign or a paywall decision is value. So when you position Data 360, the unification work is the setup and the activation is the payoff, and a use case that stops at a segment list and never publishes leaves the core benefit on the table.

### Data 360 shines where two clouds need one answer

The patterns above all live inside one team's domain. The most compelling Data 360 use cases cross those domains, because they act on data no single cloud can see alone. A calculated insight that joins Sales and Service data can flag an opportunity that is in final negotiation while the same account has a critical open case, then trigger a flow to route the case and alert the rep before the deal is at risk. Neither Sales Cloud nor Service Cloud could produce that flag alone; the insight needs both, and the flow needs the trigger.

The same shape applies to retention. A score that blends contractual entitlement with product usage can flag an adoption gap, and that flag can trigger a coaching task for the account team before the customer churns. The customer never filed a complaint; the signal came from combining what they are entitled to with what they actually use. A consultant should be able to name two or three of these cross-cloud examples on demand, because they are the clearest illustration of why a unified data foundation beats point-to-point integrations. The data does not just get consolidated; it produces a decision that was previously impossible.

### Enrichment is the low-friction first use case

Not every first use case has to open a new channel. Enrichment is the pattern of surfacing Data 360 data and insights on standard Salesforce records. Health scores, propensity values, and calculated insights can appear on Account or Contact records and related lists, giving reps context inside the workflow they already use, without building an activation destination or a new digital experience. A rep who opens an account and sees a churn-risk score and a next-best-deal flag is getting Data 360 value in a place they already trust.

Enrichment is attractive as a starting point for three reasons that all point the same direction. It is visible, because the value shows up on a record people look at every day. It is low risk, because it does not reroute a customer journey if something is wrong. And it requires no new activation destination, so it can ship while a larger personalization or advertising project is still being scoped. That combination makes enrichment a common way to prove the platform, build appetite, and earn the sponsorship to attempt the bigger, real-time patterns next.

## Config Walkthrough

Sequence a first use case in five steps.

1. Choose one high-value journey to start, for example in-session product recommendations or a churn-risk retention outreach, and write down the KPI it should move. A journey without a number attached is a feature, not a use case, and it will not survive a funding review.

2. Confirm the unifying entity, Individual or Account, is mapped to the Customer 360 Data Model and is unified by an identity resolution ruleset. Profiles and segments depend on this, so it is the first thing to verify and the first thing that silently breaks a use case if it is missing.

3. Classify each required signal as real-time or batch, and confirm the matching data streams are connected at the needed latency. Decide whether the decision happens in the moment; if it does not, do not pay for real-time.

4. Build the calculated insight or predictive score the use case needs, then build the segment or decision logic that consumes it. Keep the metric close to the outcome, so a churn use case gets a churn signal and not an unrelated vanity metric.

5. Wire the output to an action: an activation to a channel, a Data 360 triggered flow, or an enrichment on a record page, then verify the outcome against the KPI. If nothing fires and nothing changes, revisit step two, because the missing profile is usually the cause.

## Exam Traps

Three traps dominate this objective.

First, picking a use case whose unified entity is not yet mapped and unified. Profiles and segments do not exist until identity resolution has run, so the use case cannot work no matter how good the design is. If a scenario shows a segment or a personalization that never populates, the most common cause is the prerequisite: the unifying entity is not mapped and unified, so the profile does not exist. The distractor answers blame data location or segment size, but Data 360 handles lakes through federation, so storage location is not the blocker.

Second, assuming every use case needs real-time processing. Many use cases run perfectly on batch segments and daily insights, and forcing real-time adds cost and complexity for no business gain. Real-time is the right choice when the decision must land during the interaction. When a nightly refresh is good enough, a batch calculated insight and a scheduled activation will do the job for a fraction of the operational load.

Third, framing Data 360 as analytics only. The platform's value is action, so a use case that stops at a dashboard and never activates or triggers anything leaves the core benefit on the table. A report that tells a team what happened is worth something; a score that changes what happens next is worth more. When a scenario ends with a dashboard and no action, treat that as an incomplete use case rather than a finished one.

## Decision rules to carry into the exam

Match the business situation to the pattern. One agent seeing one customer's cross-channel history is a unified Customer 360 profile surfaced in the console. A same-session recommendation on a website is real-time identity resolution, real-time calculated insights, and real-time actions. A recommendation about what to do or show next is next best action or next best offer, backed by the real-time data graph. A targeted audience is segmentation and activation, gated by identity resolution. A quick, visible, low-risk win is enrichment on a standard record. And whatever the pattern, check the prerequisite first: if the unifying entity is not mapped and unified, the profile does not exist and nothing downstream can run.
