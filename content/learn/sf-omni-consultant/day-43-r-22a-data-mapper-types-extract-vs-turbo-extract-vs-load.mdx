## Deep Dive

### The four Data Mapper types each serve a different operation

OmniStudio Data Mappers are the tools that move and shape data. There are four types, and each serves a different operation: Extract reads data from Salesforce, Turbo Extract reads data from Salesforce faster, Load writes data to Salesforce, and Transform reshapes data without reading or writing [^1]. The consultant picks the type that matches the operation the business need requires.

The exam tests this directly. What are the four Data Mapper types? Extract, Turbo Extract, Load, and Transform. Extract reads data from Salesforce, Turbo Extract reads data from Salesforce faster, Load writes data to Salesforce, and Transform reshapes data without reading or writing [^1]. There is no fifth type, and the four types are the complete set the exam expects you to know.

The four types break into two natural pairs. Extract and Turbo Extract are both reads, and the difference between them is performance. Load is a write. Transform is a reshape. When the consultant knows which operation the business need requires, the type follows.

The exam is not asking you to memorize a definition; it is asking you to look at a business need and pick the type that serves it. The way to prepare is to practice the mapping from operation to type until it is automatic. When you read a scenario, you should be able to name the operation, read, write, or reshape, and then name the type that serves it. That is the skill the exam measures, and it is the skill this lesson builds.

The four types are the complete set, and the exam expects you to know all four and to know that there is no fifth type. The consultant who knows the complete set can rule out the distractors quickly and focus on the real choice.

### Extract reads data from Salesforce

A Data Mapper Extract reads data from Salesforce and returns it in JSON, XML, or a custom format [^2]. It queries Salesforce objects, filters the data, and selects the fields to return. Extracts typically provide OmniScripts, Integration Procedures, and FlexCards with the data they require [^2].

The exam tests this directly. What does a Data Mapper Extract do? It reads data from Salesforce and returns it in JSON, XML, or a custom format. An Extract queries Salesforce objects, filters the data, and selects the fields to return, typically providing OmniScripts, Integration Procedures, and FlexCards with the data they require [^2].

Here is a concrete example. A FlexCard needs to display a customer's open cases. The consultant builds an Extract that queries the Case object, filters for the customer and for open status, and selects the case number, subject, and status fields. When the FlexCard loads, it calls the Extract and receives the open cases in JSON [^2].

The Extract is the workhorse read. It supports filtering, field selection, formulas, and relationship notation, so the consultant can shape the query to return exactly the data the client needs. When the business need is to read data from Salesforce, the Extract is the type.

### Turbo Extract reads data from Salesforce faster

A Turbo Extract reads data from Salesforce faster than a standard Extract [^3]. It is optimized for performance, so it is the right choice when the business need is a high-volume or performance-sensitive read. The trade-off is that Turbo Extract has a more limited feature set than a standard Extract [^3].

The exam tests this directly. When should a consultant choose a Turbo Extract over a standard Extract? When the business need is a high-volume or performance-sensitive read. A Turbo Extract reads data from Salesforce faster than a standard Extract, so it is the right choice for high-volume or performance-sensitive reads, though it has a more limited feature set [^3].

Here is a concrete example. A dashboard needs to display a large list of records, and the read must be fast. The consultant chooses a Turbo Extract because it reads faster than a standard Extract. The dashboard loads quickly, and the user sees the data without waiting [^3].

The trade-off matters. Turbo Extract is faster, but it does not support every feature a standard Extract supports. The consultant weighs the performance need against the feature need. If the read must be fast and the data is simple, Turbo Extract wins. If the read needs complex features that Turbo Extract does not support, the standard Extract wins despite being slower.

### Load writes data to Salesforce

A Data Mapper Load writes data to Salesforce [^4]. It accepts data in JSON, XML, or a custom format and writes it to Salesforce objects. Loads handle Salesforce ID mapping, upsert logic, and error management during data creation or updates [^4].

The exam tests this directly. What does a Data Mapper Load do? It writes data to Salesforce. A Load accepts data in JSON, XML, or a custom format and writes it to Salesforce objects, handling Salesforce ID mapping, upsert logic, and error management during data creation or updates [^4].

Here is a concrete example. A user finishes entering data in an OmniScript and clicks Save. The OmniScript calls a Data Mapper Load to record the data entered. The Load maps the input data to the Salesforce object fields and writes the record [^4].

The Load is the write counterpart to the Extract. Where the Extract reads, the Load writes. When the business need is to create or update records in Salesforce, the Load is the type.

### Transform reshapes data without reading or writing

A Data Mapper Transform reshapes data without reading from or writing to Salesforce [^5]. It converts JSON to XML and vice versa, restructures input data, renames fields, and substitutes values. Transforms are essential for populating DocuSign templates and PDF documents [^5].

The exam tests this directly. What does a Data Mapper Transform do? It reshapes data without reading from or writing to Salesforce. A Transform converts JSON to XML and vice versa, restructures input data, renames fields, and substitutes values, and it is essential for populating DocuSign templates and PDF documents [^5].

Here is a concrete example. An OmniScript must populate a PDF document. The consultant builds a Transform that maps the OmniScript's data into the fields the PDF expects. The Transform reshapes the data into the PDF's format, and the PDF fills correctly [^5].

The Transform is the reshape tool. It does not touch Salesforce; it only changes the shape of the data. When the business need is to convert, restructure, or rename data, the Transform is the type.

### The performance difference between Extract and Turbo Extract

The performance difference between Extract and Turbo Extract is the key differentiator in the read pair. Turbo Extract reads faster, so it is the choice for high-volume or performance-sensitive reads, but it has a more limited feature set [^3]. The consultant weighs speed against features.

The exam tests this directly. What is the key difference between a standard Extract and a Turbo Extract? Turbo Extract reads data faster, so it is the choice for high-volume or performance-sensitive reads, but it has a more limited feature set. The standard Extract is slower but supports more features [^3].

Here is the decision in practice. A dashboard needs a fast read of a large list, and the data is simple, so the consultant chooses Turbo Extract. A complex read needs relationship notation and formulas that Turbo Extract does not support, so the consultant chooses the standard Extract despite the slower performance [^3].

The consultant does not choose Turbo Extract for every read. The choice depends on the business need. High volume and performance-sensitive, with simple data, favors Turbo Extract. Complex features favor the standard Extract.

### A worked example: choosing the type for each operation

Put the pieces together with a concrete scenario. A field service app needs to read open work orders, create a new work order, and generate a PDF of the work order details.

For the read, the app needs a fast read of a large list of open work orders, so the consultant chooses a Turbo Extract because it reads faster than a standard Extract [^3]. If the read needed complex features, the consultant would choose the standard Extract instead.

For the write, the app needs to create a new work order, so the consultant chooses a Data Mapper Load to write the data to Salesforce [^4]. The Load maps the app's input to the work order object fields and writes the record.

For the PDF, the app needs to populate a PDF document, so the consultant chooses a Data Mapper Transform to reshape the data into the PDF's format [^5]. The Transform maps the data into the fields the PDF expects.

Each operation maps to a type. The read maps to Turbo Extract, the write maps to Load, and the reshape maps to Transform. The consultant picks the type that matches the operation.

The same mapping holds when the need is stated differently. If the business need is to display a list, the operation is a read, and the type is Extract or Turbo Extract. If the business need is to save a record, the operation is a write, and the type is Load. If the business need is to convert a format, the operation is a reshape, and the type is Transform. The consultant translates the business language into the operation, and the operation names the type.

## Config Walkthrough

The four types map onto four concrete steps.

1. Choose an Extract to read data from Salesforce and return it in JSON, XML, or a custom format. Query the objects, filter the data, and select the fields to return [^2].

2. Choose a Turbo Extract when the read must be fast, for a high-volume or performance-sensitive read. Accept the more limited feature set in exchange for the speed [^3].

3. Choose a Load to write data to Salesforce. Map the input data to the object fields, and let the Load handle ID mapping, upsert logic, and error management [^4].

4. Choose a Transform to reshape data without reading or writing. Convert formats, restructure data, and rename fields, as when populating a DocuSign template or PDF [^5].

## Exam Traps

Three traps dominate this requirement, and each is a specific, avoidable mistake.

**Choosing Turbo Extract for every read.** Turbo Extract is faster but has a more limited feature set, so it is only the right choice for high-volume or performance-sensitive reads [^3]. A complex read that needs features Turbo Extract does not support should use the standard Extract.

**Using a Transform to write data to Salesforce.** A Transform reshapes data without reading or writing, so it cannot create or update records [^5]. Writing data to Salesforce is the Load's job.

**Using an Extract to write data.** An Extract reads data from Salesforce and returns it; it does not write [^2]. Creating or updating records is the Load's job.

The exam tip that ties these together: match the type to the operation. Extract and Turbo Extract read, Load writes, and Transform reshapes, and the consultant picks the type that matches the business need.
